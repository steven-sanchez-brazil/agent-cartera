      # cartera-strands-agent
      
      Agente de gestión de cartera vencida construido sobre **AWS Strands**. Recibe datos de un cliente deudor, clasifica su nivel de riesgo crediticio (BAJO / MEDIO / ALTO) y genera una recomendación de estrategia de cobranza explicada en lenguaje natural mediante Amazon Bedrock.
      
      ## Características
      
      - Clasificación determinista de riesgo basada en días de mora e incumplimientos previos.
      - Herramientas Strands (`@tool`) para `clasificar_riesgo` y `determinar_estrategia`.
      - Instrucciones del agente externalizadas en `prompt.md` para facilitar auditoría.
      - Degradación controlada ante fallos del LLM.
      - Desplegable en contenedores Docker y clusters Kubernetes.

      # ---------------------------------------------------------------------------
      # Clases de datos

      @dataclass
      class AgentResponse:
          nivel_riesgo: str            # BAJO | MEDIO | ALTO
          accion_recomendada: str      # Estrategia de cobranza
          justificacion: str           # Texto en español generado por LLM
          error: Optional[str] = None  # Mensaje de error si aplica
      
      
      # ---------------------------------------------------------------------------
      # Excepciones
      # ---------------------------------------------------------------------------
      
      class ValidationError(ValueError):
          """Entrada inválida o campos faltantes."""
      
      
      class SystemPromptError(RuntimeError):
          """prompt.md no encontrado o no legible."""
      
      
      class LLMUnavailableError(RuntimeError):
          """LLM no disponible o retornó error."""
      
      
      # ---------------------------------------------------------------------------
      # Funciones internas de soporte
      # ---------------------------------------------------------------------------
      
      def _validate_input(
          client_id: str,
          deuda: float,
          dias_mora: int,
          incumplimientos_previos: int,
      ) -> None:
          """Valida los campos de entrada.
      
          Lanza ValidationError con descripción de campos inválidos.
          """
          # 1. Verificar campos None — reporta todos los faltantes de una vez
          campos = {
              "client_id": client_id,
              "deuda": deuda,
              "dias_mora": dias_mora,
              "incumplimientos_previos": incumplimientos_previos,
          }
          campos_none = [nombre for nombre, valor in campos.items() if valor is None]
          if campos_none:
              raise ValidationError(
                  f"Campos requeridos faltantes: {', '.join(campos_none)}"
              )
      
          # 2. Verificar que client_id no sea vacío ni solo whitespace
          if not client_id.strip():
              raise ValidationError("client_id es obligatorio y no puede estar vacío")
      
          # 3. Verificar que los campos numéricos sean >= 0 — reporta todos los inválidos
          campos_negativos = [
              nombre
              for nombre, valor in [("deuda", deuda), ("dias_mora", dias_mora)]
              if valor < 0
          ]
          if campos_negativos:
              raise ValidationError(
                  f"Los valores de {', '.join(campos_negativos)} deben ser >= 0"
              )
      
      
      def _load_system_prompt(path: str = "prompt.md") -> str:
          """Lee prompt.md y retorna su contenido.
      
          Lanza SystemPromptError si el archivo no existe o no puede ser leído.
          """
          try:
              with open(path, "r", encoding="utf-8") as f:
                  return f.read()
          except FileNotFoundError:
              raise SystemPromptError(
                  f"El archivo de instrucciones del sistema no fue encontrado: '{path}'"
              )
          except PermissionError:
              raise SystemPromptError(
                  f"Sin permiso para leer el archivo de instrucciones del sistema: '{path}'"
              )
      
      
      # ---------------------------------------------------------------------------
      # Herramientas Strands (@tool)
      # ---------------------------------------------------------------------------
      
      @tool
      def clasificar_riesgo(dias_mora: int, incumplimientos_previos: int) -> str:
          """Clasifica el nivel de riesgo del cliente: BAJO, MEDIO o ALTO."""
          # Precedencia: ALTO primero, luego MEDIO, luego BAJO
          if dias_mora > 60 or incumplimientos_previos >= 2:
              return "ALTO"
          if (30 <= dias_mora <= 60) or incumplimientos_previos == 1:
              return "MEDIO"
          return "BAJO"
      
      
      @tool
      def determinar_estrategia(nivel_riesgo: str) -> str:
          """Retorna la estrategia de cobranza según el nivel de riesgo."""
          estrategias = {
              "BAJO": "Seguimiento preventivo y recordatorio de pago",
              "MEDIO": "Contacto directo y negociación de plan de pagos",
              "ALTO": "Gestión prioritaria de cobranza y evaluación de acuerdo de pago",
          }
          return estrategias[nivel_riesgo]
      
      
      # ---------------------------------------------------------------------------
      # Función pública principal
      # ---------------------------------------------------------------------------
      
      def run_agent(
          client_id: str,
          deuda: float,
          dias_mora: int,
          incumplimientos_previos: int,
      ) -> AgentResponse:
          """Ejecuta el agente de cartera vencida.
      
          Valida la entrada, carga el prompt del sistema, construye el Agent de
          Strands y delega al LLM la generación de la justificación en lenguaje
          natural.
      
          Retorna AgentResponse con nivel_riesgo, accion_recomendada y
          justificacion. En caso de fallo del LLM aplica degradación controlada.
          """
          # 1. Validar entrada (propagar ValidationError)
          _validate_input(client_id, deuda, dias_mora, incumplimientos_previos)
      
          # 2. Cargar prompt del sistema (propagar SystemPromptError)
          system_prompt = _load_system_prompt("prompt.md")
      
          # 3. Leer configuración del entorno
          region = os.environ.get("AWS_REGION", "us-east-1")
          model_id = os.environ.get(
              "BEDROCK_MODEL_ID", "anthropic.claude-3-sonnet-20240229-v1:0"
          )
      
          # 4. Construir el Agent de Strands con las herramientas
          agent = Agent(
              system_prompt=system_prompt,
              tools=[clasificar_riesgo, determinar_estrategia],
              region=region,
              model=model_id,
          )
      
          # 5. Determinar clasificación determinista y construir el mensaje
          nivel_riesgo = clasificar_riesgo(dias_mora, incumplimientos_previos)
          estrategia = determinar_estrategia(nivel_riesgo)
          mensaje = _build_llm_message(
              client_id, deuda, dias_mora, incumplimientos_previos, nivel_riesgo, estrategia
          )
      
          # 6. Invocar LLM con degradación controlada
          try:
              respuesta_llm = agent(mensaje)
              justificacion = str(respuesta_llm)
              return AgentResponse(
                  nivel_riesgo=nivel_riesgo,
                  accion_recomendada=estrategia,
                  justificacion=justificacion,
              )
          except Exception as e:
              return AgentResponse(
                  nivel_riesgo=nivel_riesgo,
                  accion_recomendada=estrategia,
                  justificacion="Justificación no disponible por error del LLM.",
                  error=f"Error en etapa LLM: {e}",
              )

## ¿Te están cobrando por usar Nova?

Sí, normalmente cada invocación exitosa de Nova mediante Bedrock genera un costo.

En tu configuración estás usando inferencia on-demand, lo que significa:

- No pagas una mensualidad fija.
- No estás reservando servidores.
- No pagas mientras el agente está apagado.
- Pagas por los tokens procesados en cada solicitud.
- Las solicitudes que fallaron antes de generar una respuesta normalmente no procesaron una inferencia completa, aunque otros servicios asociados podrían tener sus propias tarifas.

La fórmula aproximada es:

```text
costo =
(tokens de entrada / 1.000.000 × precio de entrada)
+
(tokens de salida / 1.000.000 × precio de salida)
```

Para Nova Lite, AWS publica aproximadamente:

- USD 0,06 por un millón de tokens de entrada.
- USD 0,24 por un millón de tokens de salida.

[AWS: precios de Amazon Bedrock](https://aws.amazon.com/bedrock/pricing/) y [referencia de precios Nova](https://aws.amazon.com/blogs/machine-learning/prompting-for-the-best-price-performance/).

## Ejemplo aproximado de tu prueba

Supongamos que toda la operación utilizó:

- 1.500 tokens de entrada.
- 300 tokens de salida.

El costo sería:

```text
Entrada:

= USD 0,00009

Salida:
300 / 1.000.000 × USD 0,24
= USD 0,000072

Total:
USD 0,000162
```

Eso es mucho menos de un centavo de dólar.

La cantidad real puede ser mayor porque un agente con herramientas suele realizar varios ciclos:

1. El modelo recibe el prompt.
2. Solicita ejecutar `clasificar_riesgo`.
3. Strands envía el resultado de la herramienta al modelo.
4. El modelo solicita `determinar_estrategia`.
5. Strands vuelve a enviar el resultado.
6. El modelo genera la respuesta final.

Cada ciclo agrega tokens de entrada y salida. Aun así, una prueba corta como esta normalmente cuesta una fracción muy pequeña de un centavo con Nova Lite.

## Para qué sirve AgentCore

AgentCore es útil cuando quieres pasar de una prueba local a un agente disponible como servicio en AWS.

### AgentCore Runtime

Aloja y ejecuta el agente en AWS. En lugar de tener que ejecutar:

```bash
python main.py ...
```

podrías invocarlo desde:

- Una aplicación web.
- Una API.
- Un sistema de cartera.
- Una función Lambda.
- Un proceso empresarial.
- Otro agente.

AgentCore maneja sesiones, versiones, escalado, aislamiento y ejecución administrada. AWS documenta que un agente desplegado se invoca mediante `InvokeAgentRuntime`. [AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-how-it-works.html)

### AgentCore Memory

Resultaría útil si quieres que el agente recuerde información entre interacciones, por ejemplo:

```text
Usuario: revisa el cliente 12345
Agente: riesgo ALTO

Usuario: ¿qué acuerdo recomendaste?
Agente: ...
```

Tu programa actual no mantiene conversaciones: cada ejecución comienza desde cero.

Para tu caso habría que evaluar cuidadosamente qué información se almacena, por cuánto tiempo y cómo se protegen los datos personales y financieros.

### AgentCore Gateway

Permite exponer APIs o funciones empresariales como herramientas del agente.

Por ejemplo:

```text
Agente
 ├── consultar deuda en el sistema de cartera
 ├── consultar historial de pagos
 ├── registrar gestión
 ├── crear acuerdo de pago
 └── enviar notificación
```

Actualmente tus herramientas son funciones locales y no se conectan a sistemas reales:

```python
clasificar_riesgo(...)
determinar_estrategia(...)
```

Gateway comienza a aportar valor cuando quieras conectar APIs internas, funciones Lambda o servidores MCP. [AgentCore Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-quick-start.html)

### AgentCore Identity

Sirve para autenticar usuarios y controlar qué servicios puede utilizar el agente. Por ejemplo:

- Un asesor puede consultar clientes asignados.
- Un supervisor puede aprobar acuerdos.
- El agente puede autenticarse contra una API interna.
- Las credenciales no tienen que almacenarse en `.env`.

### AgentCore Observability

Permite revisar:

- Solicitudes recibidas.
- Herramientas ejecutadas.
- Errores.
- Latencia.
- Consumo.
- Trazas del agente.
- Sesiones y comportamiento.

Al desplegar mediante AgentCore CLI, AWS puede instrumentar automáticamente el agente con OpenTelemetry y mostrar información en CloudWatch. [AgentCore Observability](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability-get-started.html)

## Qué faltaría para usar AgentCore

Como mínimo:

1. Adaptar el agente para recibir una petición, no únicamente argumentos CLI.
2. Incorporar el contrato de ejecución de AgentCore.
3. Crear un rol IAM para el runtime.
4. Darle permiso para invocar Nova en Bedrock.
5. Empaquetar las dependencias.
6. Desplegarlo en AgentCore Runtime.
7. Invocarlo usando su ARN.
8. Configurar logs, seguridad y límites de costos.

La ruta moderna mediante AgentCore CLI sería conceptualmente:

```bash
npm install -g @aws/agentcore
```

Crear o adaptar un proyecto Strands:

```bash
agentcore create \
  --project-name cartera-agentcore \
  --name CarteraAgent \
  --language Python \
  --framework Strands \
  --model-provider Bedrock \
  --memory none
```

Probar el entorno local compatible con AgentCore:

```bash
cd cartera-agentcore
agentcore dev
```

Previsualizar los recursos:

```bash
agentcore deploy --dry-run
```

Desplegar:

```bash
agentcore deploy
```

Invocar el agente desplegado:

```bash
agentcore invoke --prompt "Analiza el cliente 12345 con deuda de 8000000, 75 días de mora y 1 incumplimiento"
```

El CLI empaqueta el código, crea infraestructura y configura un endpoint de AgentCore Runtime. [Guía oficial de AgentCore CLI](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-cli.html)

No conviene ejecutar todavía esos comandos sobre tu proyecto sin adaptar el contrato de entrada y revisar los recursos que creará.
